Software Design & Engineering — OpenGL Collision Animation

Enhanced — published

A C++/OpenGL program that animates circles bouncing around a playfield, colliding with a grid of destructible bricks and with each other. Originally built for CS-330 Computational Graphics and Visualization.

The original was a single ~300-line file with global state, an all-pairs collision check that got slower as more circles were added, and a build that only worked inside Visual Studio.

  • Split the file into Brick, Circle, Physics, Renderer, and a new SpatialGrid class, and removed the global state.
  • Replaced the all-pairs collision check with spatial partitioning — circles only get compared against others sharing or bordering the same grid cell.
  • Added a CMake build (with FetchContent) so it compiles outside Visual Studio; verified with a clean build from a fresh checkout.

Demonstrates Course Outcome 3 (managing design trade-offs, via the spatial grid) and Outcome 4 (well-founded tools, via the modular structure and CMake build).

Algorithms & Data Structures — Treasure Maze Q-Learning Agent

Enhanced — published

A deep Q-learning agent that learns to navigate an 8x8 maze to a fixed target cell, built in Python with TensorFlow/Keras. Originally built for CS-370 Current/Emerging Trends in Computer Science.

The original experience replay buffer stored transitions in a plain Python list and evicted the oldest one with del self.memory[0] — an O(n) operation on every eviction — and sampled training batches completely at random.

  • Replaced the list with a deque(maxlen=max_memory), so evicting the oldest transition is O(1) instead of O(n).
  • Added prioritized experience replay, so training time goes toward the transitions the network is currently getting wrong instead of being spread evenly at random.
  • Added a breadth-first search baseline that computes the shortest possible path from every valid starting cell, so the learned path length can be measured against an objective baseline.

Demonstrates Course Outcome 3 (the BFS baseline as an objective way to evaluate the learned policy) and Outcome 4 (prioritized replay, a well-founded reinforcement-learning technique applied correctly).

Databases — Grazioso Salvare Animal Shelter Dashboard

Enhanced — published

A PyMongo CRUD wrapper and Dash/Plotly dashboard that lets Grazioso Salvare staff filter animal-shelter intake records by rescue type. Originally built for CS-340 Client/Server Development.

The original had the database password hardcoded in plaintext right next to the connection call, and every query was passed straight to MongoDB with nothing checking what was in it.

  • Credentials now come exclusively from environment variables — never from a literal in source.
  • Every query and write is checked against an allowlist of the operators the dashboard actually uses, so a NoSQL injection attempt (e.g. $where) is rejected before it reaches the database.
  • Added indexes on animal_type/breed/age_upon_outcome_in_weeks/sex_upon_outcome, matching the dashboard's actual filters.
  • Moved the breed-count chart from counting in pandas to a MongoDB aggregation pipeline.

Demonstrates Course Outcome 5 (a security mindset — finding and closing a real credential-exposure and injection vulnerability) and Outcome 4 (indexing and aggregation as the well-founded tool for the job).
