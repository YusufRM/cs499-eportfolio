Working through the Computer Science program, and especially this capstone, has given me a real way to show what I can actually do instead of just what classes I've taken. The three artifacts in this ePortfolio are an OpenGL animation, a deep Q-learning maze agent, and a MongoDB-backed rescue dashboard. They cover software design, algorithms, and databases, but the skills underneath them go further than any one artifact does.

Team collaboration. At a previous job, I worked as an engineer on an agentic donor management system, alongside engineers with different specialties than mine. That's where I actually learned what "collaborative environment" means in practice, not just as a line on a group project rubric. My part of the system had to make sense to people who weren't going to read it the way I would. Decisions about how a piece of the system worked weren't mine alone to make. That's a big part of why I care about things like removing global state and splitting code into clearly scoped modules in my Software Design enhancement. It wasn't because a rubric asked for it. I've felt what it's like to work in someone else's tangled code, and I didn't want to hand that to the next person.

Communicating with stakeholders. The clearest example of this in my program is the Grazioso Salvare dashboard from CS-340, built for shelter staff deciding which animals to train for search-and-rescue work, not for other engineers. That audience shaped real decisions. The filters are labeled by rescue type in plain language instead of database field names, and the output is a table, a chart, and a map instead of a raw query result. Enhancing that same dashboard for this capstone reinforced the same lesson from a different angle. The security and performance work underneath, things like environment-based credentials, query sanitization, and indexing, had to happen without changing anything the actual users see or interact with.

Data structures and algorithms. My Algorithms enhancement, the Treasure Maze Q-learning agent from CS-370, is where this shows up most directly. Replacing a list-based replay buffer with a deque cut eviction from O(n) to O(1). Adding prioritized experience replay meant the agent spent more of its limited training time on the moves it was actually getting wrong. I backed that up with a breadth-first search baseline, so "the agent is learning" became a number I could compare against the shortest possible path instead of just a feeling. Picking the right structure and being able to prove the choice mattered is the same instinct I want to bring into ML systems engineering work in general.

Software engineering and databases. The Software Design enhancement and the Databases enhancement both come from the same place. For Software Design, I split a single file that relied on global state into separate Brick, Circle, Physics, Renderer, and SpatialGrid classes, replaced an O(n²) collision check with spatial partitioning, and added a CMake build. For Databases, I moved credentials into environment variables, added indexes, and moved breed counts into a MongoDB aggregation pipeline. Both artifacts started as code that worked well enough to pass a course assignment but wasn't built the way I'd actually want to hand it to a team. Fixing that gap on purpose, across two very different kinds of software, is the strongest evidence I have that this wasn't a one-time thing.

Security. The Databases artifact is where a security mindset shows up most concretely. The original code had the database password typed directly into the notebook, and every query got passed straight to MongoDB with nothing checking what was in it. I closed both problems. Credentials now come only from environment variables, and every query and write gets checked against an allowlist of operators before it reaches the database, so something like a $where injection attempt gets rejected instead of executed. I tested that rejection directly instead of just asserting it works in a paragraph like this one. That's the habit I want to carry forward: a security claim I haven't actually tested is just a guess.

How these artifacts fit together. On their own, these three artifacts show design and engineering, algorithmic thinking, and database work. Put together, they're basically the range I'd want on a small systems team. I can structure a codebase so it doesn't rot. I can choose a data structure based on what it actually costs to use instead of whatever's convenient. And I can secure the layer where the data actually lives. That combination is what I'm aiming to bring into a machine learning systems engineer role, where the model is usually the smallest part of what has to work correctly. The three sections below go through each artifact in more detail: what it was, what I changed, and what I learned doing it.

Software Design & Engineering — OpenGL Collision Animation

Enhanced — published

A C++/OpenGL program that animates circles bouncing around a playfield, colliding with a grid of destructible bricks and with each other. Originally built for CS-330 Computational Graphics and Visualization.

The original was a single ~300-line file with global state, an all-pairs collision check that got slower as more circles were added, and a build that only worked inside Visual Studio.

  • Split the file into Brick, Circle, Physics, Renderer, and a new SpatialGrid class, and removed the global state.
  • Replaced the all-pairs collision check with spatial partitioning — circles only get compared against others sharing or bordering the same grid cell.
  • Added a CMake build (with FetchContent) so it compiles outside Visual Studio; verified with a clean build from a fresh checkout.

Demonstrates Course Outcome 3 (managing design trade-offs, via the spatial grid) and Outcome 4 (well-founded tools, via the modular structure and CMake build).

Algorithms & Data Structures — Treasure Maze Q-Learning Agent

Enhanced — published

A deep Q-learning agent that learns to navigate an 8x8 maze to a fixed target cell, built in Python with TensorFlow/Keras. Originally built for CS-370 Current/Emerging Trends in Computer Science.

The original experience replay buffer stored transitions in a plain Python list and evicted the oldest one with del self.memory[0] — an O(n) operation on every eviction — and sampled training batches completely at random.

  • Replaced the list with a deque(maxlen=max_memory), so evicting the oldest transition is O(1) instead of O(n).
  • Added prioritized experience replay, so training time goes toward the transitions the network is currently getting wrong instead of being spread evenly at random.
  • Added a breadth-first search baseline that computes the shortest possible path from every valid starting cell, so the learned path length can be measured against an objective baseline.

Demonstrates Course Outcome 3 (the BFS baseline as an objective way to evaluate the learned policy) and Outcome 4 (prioritized replay, a well-founded reinforcement-learning technique applied correctly).

Databases — Grazioso Salvare Animal Shelter Dashboard

Enhanced — published

A PyMongo CRUD wrapper and Dash/Plotly dashboard that lets Grazioso Salvare staff filter animal-shelter intake records by rescue type. Originally built for CS-340 Client/Server Development.

The original had the database password hardcoded in plaintext right next to the connection call, and every query was passed straight to MongoDB with nothing checking what was in it.

  • Credentials now come exclusively from environment variables — never from a literal in source.
  • Every query and write is checked against an allowlist of the operators the dashboard actually uses, so a NoSQL injection attempt (e.g. $where) is rejected before it reaches the database.
  • Added indexes on animal_type/breed/age_upon_outcome_in_weeks/sex_upon_outcome, matching the dashboard's actual filters.
  • Moved the breed-count chart from counting in pandas to a MongoDB aggregation pipeline.

Demonstrates Course Outcome 5 (a security mindset — finding and closing a real credential-exposure and injection vulnerability) and Outcome 4 (indexing and aggregation as the well-founded tool for the job).
